## 1. บทสรุปผู้บริหาร

- **ใจความ**: Digital twin ฟาร์ม = "แบบจำลองคอมพิวเตอร์ของฟาร์มจริง" ที่เชื่อมข้อมูลสด (เซนเซอร์ 05-007/05-008, ภาพดาวเทียม/โดรน 05-001/05-006, เครื่องจักร 07) + แบบจำลองพืช/น้ำ/ดิน (เชื่อม 03-001) — ใช้วัด "ถ้า...จะเกิดอะไร" (ล่วงหน้า 1–14 วัน): รดน้ำเท่าไร/เมื่อไร, ปุ๋ย/พ่นจุดไหน, คุ้มไหมที่เก็บเกี่ยว/ขายวันนี้ — เป้าหมาย: ตัดสินใจแม่นยำขึ้นแทนการลองผิดลองถูก [1][2][3]
- **ขั้นพัฒนา**: ⚗️ ยังเป็นงานวิจัย/ต้นแบบเป็นหลัก (มีระบบเชิงพาณิชย์บางส่วน — โรงเรือน/ไร่ใหญ่ต่างประเทศ) — เทคโนโลยีทุกส่วนพร้อม แต่ "การรวมเป็น twin เต็มฟาร์ม + การทำงานในแปลงจริง" ยังเป็นช่องว่าง [1][2]
- **ตัวเลขสำคัญที่สุด**: โมเดลจำลองพืช (DSSAT/APSIM-class) ใช้พยากรณ์ผลผลิตคลาดเคลื่อน ~5–15% (รายแปลง/รายฤดู — ขึ้นข้อมูล); ประหยัดน้ำ/ปุ๋ยจากการจำลองสถานการณ์ (twin + optimization) 10–30% (งานนำร่อง); ต้นทุนระบบ twin เต็มฟาร์มเริ่มต้น ~5 แสน–หลายล้านบาท (ยังแพง/แปลงใหญ่เท่านั้น) [1][2][3]
- **นัยต่อไทย**: เทคโนโลยีส่วนประกอบมีในไทยแล้ว (เซนเซอร์/โดรน/AI — หมวด 05/06) — จุดติดขัดคือ "ข้อมูลรวมศูนย์/มาตรฐาน" และ "แบบจำลองพืชไทย (ข้าว/อ้อย/ทุเรียน) ที่สอบเทียบแล้ว" — ไทยควรเริ่มจาก twin ย่อย (น้ำ/ปุ๋ย — 03-001) แล้วต่อยอดทีละชั้น [4][5][6]
- **สถานะโดยรวม**: ⚗️ งานวิจัย/ต้นแบบ

## 2. หลักการและขอบเขต

- **หลักการ**: 4 ชั้น: (1) **ข้อมูลจริง** (เซนเซอร์/ดาวเทียม/เครื่องจักร/ตลาด) (2) **แบบจำลอง** (โมเดลพืช DSSAT/APSIM — ฟิสิกส์; ML surrogate; โมเดลน้ำ/ดิน — SWAT; โมเดลเศรษฐกิจ) (3) **การผูก/สอบเทียบ** (ข้อมูลจริงอัปเดตโมเดล — data assimilation) (4) **การจำลองสถานการณ์/การตัดสินใจ** (what-if + optimization → คำแนะนำ) — ยิ่งข้อมูลสมบูรณ์ยิ่งแม่นยำ [1][2]
- **ระดับ twin**: (ก) twin ระบบเดียว (น้ำ/ปุ๋ย/โรงเรือน — ง่ายสุด มีใช้จริง) (ข) twin ระดับแปลง (หลายระบบรวม) (ค) twin ทั้งฟาร์ม/ห่วงโซ่ (เต็มรูปแบบ — งานวิจัย)
- **ความถี่อัปเดต**: สด–รายวัน (เซนเซอร์) / รายสัปดาห์ (ดาวเทียม) — การพยากรณ์ล่วงหน้า 1–14 วัน (ขึ้นแบบจำลองอากาศ — เชื่อม 05-008/11)
- **ขอบเขตที่ครอบคลุม**: เทคโนโลยี/สถานะ, ราคา/ตลาด, งานไทย, แนวทางใช้
- **นอกขอบเขต**: แบบจำลองเฉพาะระบบ (03-001/04-005/02-012), เซนเซอร์/ข้อมูล (05), AI ตัวเดียวหลายงาน (06-003)

## 3. สถานะงานวิจัย

| ช่วงเวลา    | ความก้าวหน้า                                                                                                                     | แหล่ง  |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 1970s–2000s | แบบจำลองพืช (CERES→DSSAT, APSIM, WOFOST) — งานวิจัยจำลองผลผลิต/น้ำ                                                               | [1]    |
| 2010s       | "Digital twin" (จากอุตสาหกรรม — NASA/Gartner) เข้าสู่เกษตร; งาน twin น้ำ/โรงเรือนเริ่ม                                           | [1][2] |
| 2020–2023   | twin โรงเรือน/ฟาร์มนำร่อง (ยุโรป/เนเธอร์แลนด์ — เช่น งาน VF 04-005); data assimilation + ML surrogate                            | [1][2] |
| 2024–2026   | Foundation models (06-003) มาเป็น "สมอง" ของ twin; งาน twin ระดับฟาร์ม+ตลาด; ความสนใจสูง (Nature Food) — แต่ผลงานแปลงจริงยังน้อย | [2][3] |
| 2026–       | แนวโน้ม: twin ราคาถูกลง (การรวมซอฟต์แวร์/API), การผูกกับ LLM (ถามฟาร์มเป็นภาษา — เชื่อม 06-002), มาตรฐานข้อมูล                   | [3]    |

- **เส้นแบ่ง**: "ทฤษฎี/ระบบนำร่อง" ก้าวไกล — "การทำงานจริงในฟาร์มไทย/แปลงเล็ก + การพิสูจน์ผลตอบแทน" ยังไม่มี; ปัญหาหลัก: ข้อมูลไม่สมบูรณ์/ไม่มาตรฐาน, การสอบเทียบแบบจำลองรายพื้นที่, ต้นทุน/ทักษะ

## 4. ผลลัพธ์เชิงประจักษ์ (ตัวเลข)

| ตัวชี้วัด                                 | ผลลัพธ์                                       | เงื่อนไข                   | แหล่ง  |
| ----------------------------------------- | --------------------------------------------- | -------------------------- | ------ |
| ความแม่นยำโมเดลพืช (DSSAT/APSIM — ผลผลิต) | คลาดเคลื่อน 5–15% (รายแปลง/ฤดู)               | ข้อมูลครบ/สอบเทียบ         | [1]    |
| ประหยัดน้ำ/ปุ๋ย (twin+optimization)       | 10–30% (งานนำร่อง)                            | ระบบชลประทาน/ปุ๋ยควบคุมได้ | [2]    |
| การพยากรณ์ล่วงหน้า (what-if)              | 1–14 วัน (ขึ้นแบบจำลองอากาศ)                  | งาน                        | [2]    |
| ต้นทุนระบบ twin เต็มฟาร์ม                 | ~5 แสน–หลายล้านบาท (เริ่มต้น)                 | ตลาด/งาน                   | [3]    |
| ข้อมูลที่ต้องป้อน                         | เซนเซอร์ ≥10–30 จุด/แปลง + อากาศ + ดิน (ช่วง) | งาน                        | [2]    |
| การสอบเทียบ (calibration) ต้องมีข้อมูล    | ≥1–3 ฤดู (งานวิจัย)                           | งาน                        | [1]    |
| ผลตอบแทน (ไร่ใหญ่ต่างประเทศ)              | กำไร +5–15% (งาน/บริษัท — ช่วง)               | งาน/บริการ                 | [2][3] |

- **กฎ**: ความแม่นยำของ twin = คุณภาพข้อมูล + การสอบเทียบ — "twin สวยแต่ข้อมูลไม่จริง" ให้ผลหลอก; คุ้มเฉพาะแปลงใหญ่/ระบบควบคุมอัตโนมัติ/พืชมูลค่าสูง
- **เงื่อนไขสำคัญ**: (1) มาตรฐานข้อมูล/การรวมศูนย์ (2) แบบจำลองพืชไทยที่สอบเทียบ (3) ระบบควบคุม (น้ำ/ปุ๋ย — 03-001/02-012) ที่ทำตามคำแนะนำได้จริง (4) ทักษะ/บุคลากร (5) ต้นทุนต่อประโยชน์

## 5. ตลาดและการลงทุน

- **ขนาดตลาด**: Digital twin การเกษตร ~0.5–2 พันล้านดอลลาร์ (2025 — analyst estimate ยังไม่ยืนยัน); โต 25–40%/ปี (ฐานเล็ก) [3]
- **ผู้เล่นหลัก**: ซอฟต์แวร์โมเดล (DSSAT/APSIM — วิจัย/เปิด), แพลตฟอร์ม (Climate FieldView, John Deere Ops Center, Netafim GrowSphere, CropX — twin ย่อย), งานวิจัย (EU — หลายโครงการ, จีน), ไทย: ยังไม่มีบริการ twin เต็มฟาร์ม (มี twin ย่อยน้ำในงานวิจัย — เชื่อม 03-001) [2][3][4][5]
- **การลงทุน**: เริ่มจาก twin ย่อย (น้ำ/ปุ๋ย — ใช้โมเดล+เซนเซอร์ที่มี 03-001/05-007) หลักหมื่น–แสนบาท; twin เต็มฟาร์มยังเป็น "โชว์เคส" (บริษัทใหญ่/โครงการวิจัย) — ตลาดไทยอยู่ช่วง "พิสูจน์คุณค่า"
- **แนวโน้ม**: การผูก LLM (ถาม-ตอบภาษาไทย — 06-002), twin ราคาถูกลง (API/cloud), การรวมมาตรฐานข้อมูล (สำคัญที่สุด), การใช้ในการประกันภัย/คาร์บอน/การขายล่วงหน้า (เชื่อม 11/02-002/12)
- **ความเสี่ยง**: การตลาดเกินจริง (demo สวย — ผลจริงยังไม่พิสูจน์), ต้นทุน/ทักษะสูง, ข้อมูลไม่พร้อม, การพึ่งผู้ขายรายเดียว

## 6. สถานการณ์ประเทศไทย

- **สถานะ**: มีส่วนประกอบครบ (เซนเซอร์ 05-007/05-008, โดรน 05-006, ดาวเทียม 05-001/05-010, AI 06) แต่ "twin รวมฟาร์ม" ยังไม่มีบริการไทย — งานวิจัย twin ย่อย (น้ำในแปลงอ้อย/ข้าว — มก./มข./มจธ.; โรงเรือน 04-005) มีอยู่จริง; ข้อมูลกระจัดกระจาย (หน่วยงาน/บริษัทคนละระบบ) [4][5][6]
- **จุดแข็งไทย**: เซนเซอร์/โดรน/ข้อมูลมีแล้ว, งานวิจัยแบบจำลอง (DSSAT ข้าว/อ้อย — มหาวิทยาลัย/กรมวิชาการ) มี, พืชสำคัญ (ข้าว/อ้อย/ทุเรียน) มีข้อมูลงานวิจัยมาก, แพลตฟอร์มข้อมูลเริ่มมี (GISTDA/กรมส่งเสริม)
- **จุดอ่อน**: ไม่มีระบบรวมศูนย์/มาตรฐานข้อมูล, การสอบเทียบแบบจำลองรายพื้นที่ยังไม่เป็นระบบ, บุคลากร AI/จำลองจำกัด, ราคา/การยอมรับ, twin ยังเป็นงานวิจัยไม่ใช่บริการ
- **โอกาส**: (1) "แพลตฟอร์มข้อมูลฟาร์มกลาง" (มาตรฐานเดียว — ต่อยอด GISTDA/กรมส่งเสริม) (2) twin ย่อยเชิงพาณิชย์ (น้ำ/ปุ๋ย — เชื่อม 03-001/02-012) ต่อไร่ (3) งานไทย: twin ข้าว/อ้อยกับโรงงาน/สหกรณ์ (4) การผูกกับประกันภัย/คาร์บอน (11/02-002)
- **หน่วยงาน**: GISTDA (ข้อมูล/แพลตฟอร์ม), กรมส่งเสริมการเกษตร/สศก., มหาวิทยาลัย (มก./มข./มจธ.), โรงงานน้ำตาล/บริษัท AgTech

## 7. ช่องว่างงานวิจัย (Open Questions)

- **Q1**: มาตรฐานข้อมูลฟาร์มไทย (เซนเซอร์/เครื่องจักร/ดาวเทียม — รูปแบบเดียว) — ยังไม่มี
- **Q2**: การสอบเทียบ DSSAT/APSIM-class สำหรับข้าว/อ้อย/ทุเรียนไทย รายภูมิภาค (ชุดข้อมูลเปิด) — ยังไม่ครบ
- **Q3**: twin ย่อยเชิงพาณิชย์ (น้ำ/ปุ๋ย) ที่คืนทุนได้จริงในแปลงไทย (ROI — ต่อยอด 03-001/02-012) — ยังไม่มี
- **Q4**: การรวม LLM (06-002) กับ twin — เกษตรกรถาม/สั่งงานด้วยภาษาไทยได้จริง? — ยังไม่มีงาน
- **Q5**: twin ระดับห่วงโซ่ (แปลง→ตลาด→ราคา) ไทย — ยังไม่มี
- **Q6**: การยอมรับ/การจ่ายเงินของเกษตรกรไทยต่อบริการ twin (ต่อยอด 14-003) — ยังไม่มี

| ---------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |

| 2 (2–4 ปี) | บริการ "twin น้ำ/ปุ๋ยต่อไร่" (ผู้ประกอบการ); งาน twin ข้าว/อ้อยกับโรงงาน/สหกรณ์ (พยากรณ์ผลผลิต/แผนรับซื้อ)                      | แพลตฟอร์มข้อมูลกลางเปิด (API); การใช้ twin ในการวางแผนภัยแล้ง/น้ำ (เชื่อม 11)                           |
| 3 (4+ ปี)  | "twin ฟาร์มเต็มรูปแบบ" (อากาศ+ดิน+พืช+เครื่องจักร+ตลาด) สำหรับฟาร์มใหญ่/บริษัท — ผูก LLM/GenAI (06-002) และการตัดสินใจอัตโนมัติ | นโยบาย "ฟาร์มดิจิทัล" (ข้อมูลเป็นสาธารณูปโภค); การใช้ twin ในการประกันภัย/คาร์บอน/ส่งออก (11/02-002/12) |

## 9. ความท้าทายและข้อจำกัด

| ความท้าทาย              | รายละเอียด                            | โอกาสแก้                                  |
| ----------------------- | ------------------------------------- | ----------------------------------------- |
| ข้อมูลไม่ครบ/ไม่มาตรฐาน | เซนเซอร์หลายยี่ห้อ/คนละระบบ           | มาตรฐานกลาง, API/การผูกข้อมูล             |
| การสอบเทียบแบบจำลอง     | รายพื้นที่/พันธุ์ ต้องใช้ข้อมูลหลายปี | ฐานเปิด/งานวิจัยร่วม, surrogate ML        |
| ต้นทุน/ทักษะ            | ระบบแพง/คนทำไม่พอ                     | เริ่ม twin ย่อย, บริการ/cloud, อบรม       |
| การยอมรับ               | เกษตรกรไม่เห็นประโยชน์ทันที           | สาธิต ROI, แอปง่าย/ภาษาไทย                |
| การพิสูจน์ผลตอบแทน      | ผลจริงยังไม่ชัด (ต่างปี/แปลง)         | วัดผลระยะยาว, แปลงสาธิต                   |
| ความน่าเชื่อถือแบบจำลอง | โมเดลผิด → คำแนะนำผิด (ความเสี่ยง)    | การสอบเทียบ/การแสดงความไม่แน่นอน (06-005) |

## 11. อภิธานศัพท์

| คำศัพท์                | ความหมาย                                    |
| ---------------------- | ------------------------------------------- |
| Digital twin           | แบบจำลองดิจิทัลของระบบจริง (อัปเดตข้อมูลสด) |
| What-if simulation     | การจำลอง "ถ้า...จะเกิดอะไร"                 |
| DSSAT/APSIM            | แบบจำลองการเจริญพืช (มาตรฐานงานวิจัย)       |
| Data assimilation      | การอัปเดตแบบจำลองด้วยข้อมูลจริง             |
| Surrogate model        | แบบจำลอง ML แทนโมเดลฟิสิกส์ (เร็วขึ้น)      |
| Calibration            | การสอบเทียบพารามิเตอร์ต่อพื้นที่/พันธุ์     |
| Twin (ระดับ)           | ระบบเดียว / แปลง / ทั้งฟาร์ม                |
| Optimization           | การหาคำตอบที่ดีที่สุด (น้ำ/ปุ๋ย/เวลาขาย)    |
| Open API               | การเชื่อมข้อมูลมาตรฐานระหว่างระบบ           |
| Digital twin (ห่วงโซ่) | twin ต่อยอดถึงตลาด/ราคา/โลจิสติกส์          |
