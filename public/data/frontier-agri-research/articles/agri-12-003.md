## 1. บทสรุปผู้บริหาร

- **ใจความ**: "ข้อมูลฟาร์ม" (ผลผลิต ดิน เครื่องจักร สภาพอากาศ ภาพถ่ายแปลง) กำลังกลายเป็นสินทรัพย์เศรษฐกิจใหม่ของเกษตรกรรมดิจิทัล — ฟาร์มเฉลี่ยจะผลิตข้อมูลมากกว่า 4.1 ล้านจุด/วัน ภายในปี 2050 [2] และตลาด smart agriculture โลกมีมูลค่า ~US$25.4 พันล้าน (2024) คาดโตถึง US$83.7 พันล้าน (2033) CAGR 14.6% [1] — แต่คำถาม "ใครเป็นเจ้าของข้อมูลฟาร์ม" ยังไม่มีคำตอบทางกฎหมายตายตัว โลกจึงตอบด้วย 3 กลไกขนาน: (1) กฎหมาย (EU Data Act มีผล 2025-09-12 ให้สิทธิ์ผู้ใช้เครื่องจักรเข้าถึงข้อมูลที่เครื่องสร้างฟรี) [3][8] (2) ภาคสมัครใจ (US Farm Data Principles 2014–2024 มีองค์กรยอมรับแล้ว 37+ [4], EU Code of Conduct 2018 ว่าด้วย "data originator" คือเกษตรกร [10], Australian Farm Data Code 2020 [13]) (3) โครงสร้างตลาดใหม่ (data spaces/CEADS [15], data marketplace [27], data cooperative/trust [28][26])
- **ขั้นพัฒนา**: 🏭 กฎหมาย/กรอบบังคับใช้แล้วใน EU (Data Act 2025-09-12 [3]); 🇦🇺🇺🇸 กรอบสมัครใจใช้แล้ว; 🧪 ตลาดกลางข้อมูลจริง (data marketplace) ยังเป็นนำร่อง/เริ่มต้น (NASDA UK, AgriAICoop ยังไม่เปิดตลาดจริง [26][28]); 🔬🧪 ไทยยังวิจัย-นำร่อง (AgriNEXT-สวทช. ยัง R&D [7], สศก./Agri-Map เป็นการเปิดข้อมูลภาครัฐ [24][25])
- **ตัวเลขสำคัญที่สุด**: Data Act มีผลบังคับใช้แล้วตั้งแต่วันที่ 2025-09-12 ครอบคลุมเครื่องจักรเกษตรที่ขายใน EU [3][8]; EU มี data-sharing initiatives มากกว่า 400 รายการที่ถูกแมปเพื่อสร้าง CEADS (งบ AgriDataSpace €2 ล้าน) [14]; เคนยามีโปรไฟล์เกษตรกรดิจิทัล >6 ล้านรายในระบบ KIAMIS [6]; งานสำรวจออสเตรเลีย (1,000 ฟาร์ม/17 อุตสาหกรรม) พบเกษตรกร 3 ใน 4 ไม่รู้เงื่อนไข T&C ของผู้ให้บริการ และกว่าครึ่งไม่ไว้วางใจผู้ให้บริการข้อมูล [5]; ไทย: Agri-Map มีชั้นข้อมูล >200 ชั้น [24], กรมส่งเสริมการเกษตรถือทะเบียนเกษตรกรกลางตามระเบียบ พ.ศ. 2567 ภายใต้ PDPA [33]
- **นัยต่อไทย**: ไทยมี "ข้อมูลมหาศาลแต่ไร้ตลาด" — ระบบเปิดข้อมูลภาครัฐดีอยู่ (OAE Catalog/Agri-Map) แต่ขาด (1) มาตรฐานการแลกเปลี่ยน/สิทธิ์ข้อมูลฟาร์มภาคเอกชน (2) แนวทาง PDPA เฉพาะข้อมูลฟาร์ม (3) กลไกให้เกษตรกรได้ส่วนแบ่งมูลค่าจากข้อมูล — เสี่ยงที่ข้อมูลแปลงไทยจะถูกรวบรวมโดยแพลตฟอร์มต่างชาติโดยเกษตรกรได้ผลตอบแทนน้อย เหมือนข้อกังวลที่พบในเคนยา/ออสเตรเลีย [6][5]
- **สถานะโดยรวม**: 🏭 เชิงพาณิชย์แล้ว (กรอบกฎหมาย/สมัครใจต่างประเทศ) — 🧪 ตลาดกลาง/ไทยยังนำร่อง

## 2. หลักการและขอบเขต

- **หลักการทำงาน (3 ชั้นของธรรมาภิบาลข้อมูลเกษตร)**:
  1. **ชั้นกฎหมาย (binding)**: EU Data Act (Regulation (EU) 2023/2854) — ใช้บังคับ 2025-09-12 — ให้ "ผู้ใช้" (user = ผู้ซื้อ/เช่าเครื่องจักร เช่น เกษตรกร) มีสิทธิ์เข้าถึงข้อมูลที่เครื่องจักรสร้างได้โดยตรง ฟรี ทันที และสั่งให้ผู้ถือข้อมูล (ผู้ผลิตเครื่อง) ส่งข้อมูลต่อให้บุคคลที่สามที่ผู้ใช้ระบุ (Article 4/5) — ข้อจำกัดสำคัญ: ข้อมูล "ที่ถูกประมวลผล/อนุมาน" (derived data เช่น คำแนะนำปุ๋ยจากอัลกอริทึม) อยู่นอกขอบเขต (Recital 15) และยกเว้นผู้ถือข้อมูลที่เป็น SME [3][8][9]; เคนยามี Data Protection Act 2019 กำกับข้อมูลส่วนบุคคลของเกษตรกร [11]; ไทยมี PDPA พ.ศ. 2562 (มีผล 2565) [34]
  2. **ชั้นภาคสมัครใจ (voluntary codes)**: US Privacy & Security Principles for Farm Data (2014, อัปเดต 2024 โดย Ag Data Transparent — 37+ องค์กร) ยึดหลัก "ข้อมูลที่เกิดจากฟาร์มเป็นของเกษตรกร" + ต้องแจ้งหากนำข้อมูลไปฝึก AI/ML [4]; EU Code of Conduct on Agricultural Data Sharing (2018, โดย COPA-COGECA/CEMA/FEFAC ฯลฯ) — "data originator" (ผู้สร้างข้อมูล = เกษตรกร) ควบคุมการเข้าถึง/ใช้ข้อมูล [10]; Australian Farm Data Code (NFF, 2020) — แบ่งข้อมูลเป็น Farm Data/Private Data/Public Data ใช้หลักความโปร่งใส-เป็นธรรม-พกพาได้ [13][12]
  3. **ชั้นเทคนิค/โครงสร้างตลาด (interoperability)**: มาตรฐานเครื่องจักร ISOBUS/ISOXML, API เปิด (OADA ใช้ REST + OAuth 2.0 [38]), data space แบบกระจายศูนย์ (CEADS/GAIA-X/IDS [15][16][27]) และ data marketplace (แพลตฟอร์มซื้อ-ขาย/อนุญาตใช้ข้อมูล เช่น Agrimetrics UK, JoinData NL, AgDataHub FR [27]) — รวมถึงรูปแบบใหม่: data trust/สหกรณ์ข้อมูล (NASDA UK ให้เกษตรกรได้ 95% ของกำไรขายข้อมูล [26], AgriAICoop หนึ่งสมาชิกหนึ่งเสียง [28])
- **เส้นแบ่งแนวคิด**: ตลาดกลางข้อมูล 2 รูปแบบ — (ก) แบบรวมศูนย์ (marketplace — เหมือนตลาดสด: ข้อมูลขายตรง) กับ (ข) แบบกระจายศูนย์ (data space — เหมือนเครือข่ายถนน: ข้อมูลแลกกันแบบ peer-to-peer ภายใต้กฎร่วม) — ปัจจุบันแนวโน้มโลกเอียงไปทาง (ข) เพื่อแก้ปัญหา lock-in และความเป็นเจ้าของ [27][35][37]
- **ขอบเขตที่ครอบคลุม**: ความเป็นเจ้าของ/สิทธิ์ข้อมูลฟาร์ม, มาตรฐานการแลกเปลี่ยน (interoperability), ตลาดกลางข้อมูล/data space/data trust/สหกรณ์ข้อมูล, กรณีศึกษา EU/US/AU/Kenya/ไทย, PDPA กับข้อมูลฟาร์ม, ข้อมูลฟาร์มในฐานะชุดฝึก AI
- **นอกขอบเขต**: รายละเอียดเชิงเทคนิคของแพลตฟอร์มฟาร์ม/เซนเซอร์ (06-006), กฎหมาย PDPA/ข้อมูลส่วนบุคคลโดยทั่วไป (06-010), การค้า/EUDR เจาะลึก (12-004), เศรษฐศาสตร์ precision ag ภาพรวม (12-001)

## 5. ตลาดและการลงทุน

- **ขนาดตลาด**: ตลาด smart agriculture ~US$23.2–26.3 พันล้าน (2025) โต CAGR ~12–15% ไปสู่ US$72–84 พันล้าน (2033–2035) [1][21][22]; ตลาด "ข้อมูลเกษตร" ยังไม่มีตัวเลขแยกที่เชื่อถือได้ — อยู่ในส่วนหนึ่งของตลาด farm management software/data services [27][2]
- **ผู้เล่นหลัก (ระดับโลก)**:
  - **แพลตฟอร์มเครื่องจักร/เมล็ดพันธุ์**: John Deere (Ops Center), Climate FieldView (Bayer), Syngenta Cropwise, Corteva — ผูกข้อมูลกับอุปกรณ์/พันธุ์ [27]
  - **Data space/เครือข่าย**: CEADS (EU, 36 องค์กร [15]), AEF AgIN (เปิด production 9/2026 — สมาชิก AEF 280+ องค์กร [19][36][40]), DKE agrirouter (เยอรมนี), GAIA-X/IDS architecture [27][37]
  - **Data marketplace**: Agrimetrics (UK — ผูกพันกับ Microsoft FarmBeats/UK Agri-Tech Centre), JoinData (เนเธอร์แลนด์ — สหกรณ์นมมีบทบาทนำ), AgDataHub (ฝรั่งเศส), DJustConnect (เบลเยียม), Agrifood Data Space (ฟินแลนด์) [27]
  - **สหกรณ์ข้อมูล/data trust**: NASDA UK (95% รายได้คืนเกษตรกร [26]), AgriAICoop (หนึ่งสมาชิกหนึ่งเสียง ยังอยู่ในช่วง build [28]), AgriData Coop (Fargo ND ก่อตั้ง 2025 [29]), NCDHIP/DRPC (สหกรณ์ข้อมูลโคนมสหรัฐฯ ดำเนินการมา 70+ ปี — ต้นแบบที่เก่าแก่สุด) [27]
  - **ภาครัฐ/นานาชาติ**: EU (Data Act/DGA/CEADS [3][15]), เคนยา (KIAMIS + ร่างกฎหมาย 2026 [17][20]), FAO/GODAN (เปิดข้อมูล) [27], ออสเตรเลีย (NFF Farm Data Code [13])
- **การลงทุน/โมเดลรายได้**: AgriDataSpace/CEADS ใช้เงินสาธารณะ (€2 ล้าน + งบ Digital Europe ระยะต่อไป) [14][15]; AgIN เก็บค่าสมัครเข้าร่วม dataspace ครั้งเดียว + ค่าบำรุง (บริษัทผู้ผลิตเครื่องเป็นผู้จ่าย) [36]; marketplace แบบ NASDA UK หักค่าบริการ 5% [26]; ยังไม่มีตัวเลขเปิดของยอดซื้อขายข้อมูลจริง (flag: สมมติฐานข้อ 10)
- **ปัจจัยขับเคลื่อน**: (1) Data Act บังคับให้เปิดข้อมูลเครื่องจักร → เกิดตลาดบริการใหม่ [3] (2) EUDR/การตรวจสอบย้อนกลับ → ความต้องการข้อมูลพิสูจน์แหล่งผลิต (AgriTrust ใช้ blockchain+data contract ตอบโจทย์นี้ [30]) (3) AI ต้องการชุดข้อมูลฝึกจากฟาร์มจริง (ทุกแพลตฟอร์มผูก AI — ADT กำหนดให้เปิดเผยการใช้ฝึก AI [4]) (4) ภาครัฐอยากได้ข้อมูลวางนโยบาย (CEADS เชื่อม CAP [15])
- **ปัจจัยฉุดรั้ง**: ความไม่ไว้วางใจของเกษตรกร (ออสเตรเลีย: 75% ไม่รู้ T&C [5]; เคนยา: เกษตรกรกังวลภาษี/การแอบแชร์ข้อมูล [6]), lock-in ของแพลตฟอร์มใหญ่ [27], การตั้งราคาข้อมูลไร้มาตรฐาน [2], ปัญหา "ข้อมูลเป็นสินค้า non-rival" (ใช้ร่วมกันได้ไม่หมด — ซ้ำขายได้หลายครั้ง) [27][2], SME ผู้ผลิตเครื่องถูกยกเว้น Data Act → ช่องโหว่ [8]

## 6. สถานการณ์ประเทศไทย

- **งานวิจัย/แพลตฟอร์มไทย**:
  - 🔬🧪 **AgriNEXT (เนคเทค-สวทช.)** — แพลตฟอร์มบูรณาการข้อมูล IoT ในแปลง (ต่อยอด WiMaRC) + ภาพถ่ายดาวเทียม (REM) ประมวลผลด้วย AI เพื่อวางแผนผลิต/พยากรณ์ผลผลิต — **ยังอยู่ในขั้นวิจัยและพัฒนา**; ทดลองจริง 2568: ติดตามปุ๋ย NANO nCote ในแปลงข้าว ร้อยเอ็ด-ศรีสะเกษ (โครงการทุ่งกุลาม่วนซื่น) [7]
  - 🟢 **Agri-Map (กระทรวงเกษตรฯ + เนคเทค)** — แผนที่เกษตรเชิงรุก เริ่ม 2559, ชั้นข้อมูล >200 ชั้น, ครอบคลุม 76 จังหวัด, มี Agri-Map Online/App — เปิดบริการแล้ว [24][31]
  - 🟢 **What2Grow (เนคเทค)** — ระบบแนะนำพืชทดแทนจากข้อมูลหน่วยงานหลายแห่ง (แผนที่/ผลผลิต/ราคา/แหล่งรับซื้อ) — ให้บริการแล้ว [31]
  - 🟢 **OAE Catalog (สศก.)** — ระบบบัญชีข้อมูล CKAN เปิด API v3 ราคาสินค้า/ผลผลิต/การค้า/ครัวเรือนเกษตรกร/GDP เกษตร [25]
  - 🟡 **ศูนย์ข้อมูลเกษตรแห่งชาติ (NABC)/AgriDataProv (สศก.)** — แพลตฟอร์ม Big Data เกษตรระดับจังหวัด ยังอยู่ในช่วงพัฒนาระบบ (มีประกาศจ้างพัฒนาปีงบ 2568) [32]
  - 🟡 **แพลตฟอร์มแปลงเกษตร AgriSpace (มก./KU)** — วิเคราะห์แปลงจากดาวเทียม ML/AI แดชบอร์ดรายรับ-รายจ่าย — บริการนำร่อง [อ้างอิง: เว็บ KU — ยังไม่ยืนยันสถานะล่าสุด ดูข้อ 10]
  - 🟢 **ทะเบียนเกษตรกรกลาง (กรมส่งเสริมการเกษตร)** — ระบบขึ้นทะเบียน ทบก. ตามระเบียบคณะกรรมการนโยบายฯ ว่าด้วยการขึ้นทะเบียนเกษตรกร พ.ศ. 2567 — มีประกาศความเป็นส่วนตัว PDPA ครบถ้วน [33]
- **ภาคเอกชนไทย**: สตาร์ทอัพ AgTech เก็บข้อมูลแปลง (โดรน/ปุ๋ย/เครื่องจักร) แต่ไม่มีการแลกเปลี่ยนข้อมูลระหว่างราย — เชื่อมโยง 14-002; ยังไม่มี "ตลาดกลางข้อมูล" หรือสหกรณ์ข้อมูลเชิงพาณิชย์ในไทย [27][33]
- **กฎหมาย/นโยบาย**:
  - **PDPA พ.ศ. 2562** (มีผล 2565) — บังคับทุกธุรกิจที่เก็บข้อมูลส่วนบุคคล ข้อมูลฟาร์มที่ระบุตัวเกษตรกรได้ (ชื่อ ที่อยู่ พิกัด GPS ภาพแปลง) เข้าข่ายข้อมูลส่วนบุคคล; ยังไม่มีแนวทางเฉพาะ "ข้อมูลฟาร์ม" เหมือน EU Code of Conduct/ADT — สป.กษ. มีนโยบายคุ้มครองข้อมูล + ธรรมาภิบาลข้อมูลภาครัฐตามประกาศคณะกรรมการพัฒนารัฐบาลดิจิทัล [34][12]
  - **สพร. (DGA)** — ดูแลธรรมาภิบาลข้อมูลภาครัฐ, GDX (ศูนย์แลกเปลี่ยนข้อมูลกลาง), Open Government Data [35]
  - ยังไม่มี: กฎหมาย "สิทธิ์ข้อมูลฟาร์ม" แบบ Data Act, มาตรฐานรหัสแปลงเดียวเปิด, แนวทางยินยอมเฉพาะเกษตร (ไม่ต่างจาก 06-006/12-001)
- **จุดแข็งไทย**: ฐานข้อมูลภาครัฐเข้มแข็ง (ทะเบียนเกษตรกร/Agri-Map/OAE Catalog [24][25][33]); PDPA ครอบคลุมความเป็นส่วนตัว [34]; มีหน่วยงานวิจัยครบวงจร (สวทช./มก./สศก.) [7][25]; ความต้องการตรวจสอบย้อนกลับ EUDR กำลังสร้างแรงกดดันให้ต้องมีข้อมูลคุณภาพ [30]
- **จุดอ่อน**: ไม่มีมาตรฐานการแลกเปลี่ยนข้อมูลภาคเอกชน/ไม่มีตลาดกลาง; ไม่มีแนวปฏิบัติ "การยินยอม-แบ่งปันผลประโยชน์" ข้อมูลฟาร์มภาษาไทย; เกษตรกรรายย่อย (แปลงเล็ก) ขาดอำนาจต่อรองและเข้าถึงแพลตฟอร์มน้อย; ข้อมูลภาครัฐ-เอกชนแยกส่วน [25][33]
- **รอบตรวจสอบถัดไป: 2027-02-02**

## 7. ช่องว่างงานวิจัย (Open Questions)

- **Q1**: สิทธิ์ "ความเป็นเจ้าของ" ข้อมูลฟาร์มในกฎหมายไทยควรออกแบบอย่างไร (ยืมแนวคิด data originator ของ EU [10] vs หลัก "เกษตรกรเป็นเจ้าของ" ของสหรัฐฯ [4]) — ยังไม่มีงานวิเคราะห์กฎหมายไทยในบริบทนี้
- **Q2**: มูลค่าทางเศรษฐกิจของข้อมูลแปลงไทย (บาท/แปลง/ปี) ควรตั้งราคาอย่างไร — ยังไม่มีงานประเมิน (ต่างประเทศก็เพิ่งเป็น simulation [2])
- **Q3**: ความเต็มใจให้ข้อมูลของเกษตรกรไทย (ยินยอมแลกกับบริการอะไร) — ยังไม่มีการสำรวจระดับชาติ (งานออสเตรเลีย/เคนยาไม่ถ่ายโอนตรง [5][6])
- **Q4**: Data Act ใช้กับเครื่องจักรนำเข้าที่ขายในไทย/ส่งออกไป EU อย่างไร (เครื่องจักร CNH/John Deere ที่ทำตลาดไทย) — ยังไม่มีงานไทยวิเคราะห์ผลกระทบ
- **Q5**: สถาปัตยกรรม "data space ไทย" (รหัสแปลงเดียว + consent broker + API มาตรฐาน) เทียบต้นทุนกับ marketplace รวมศูนย์ — ยังไม่มีงานออกแบบ
- **Q6**: การใช้ข้อมูลฟาร์มฝึกโมเดล AI โดยไม่ได้เปิดเผย — มีงานต่างประเทศกำหนดแนวทาง (ADT 2024 [4]) แต่ยังไม่มีงานวิจัยไทยว่าต้องมีกฎ/กลไกกำกับอย่างไร

## 8. นัยต่อการนำไปใช้ (Blueprint)

### Blueprint สำหรับไทย (เรียงตามลำดับ)

1. **มาตรฐาน "รหัสแปลงเดียว" + คลังข้อมูลเปิด (1–2 ปี)** — รวมทะเบียนเกษตรกร/Agri-Map/OAE Catalog/GISTDA เข้าบัญชีข้อมูลเดียว เปิด API มาตรฐาน (ต่อยอด CKAN ของ สศก. [25] + ธรรมาภิบาลข้อมูลภาครัฐ สพร. [35])
2. **แนวปฏิบัติ "การยินยอมข้อมูลฟาร์ม" ภาษาไทย (1–2 ปี)** — ออกคู่มือ PDPA+เฉพาะเกษตร (เลียนแบบ EU Code of Conduct [10]/Farm Data Code [13]): เก็บอะไร ใช้ทำอะไร ใครเห็น เกษตรกรถอนได้ — ใช้กับบริษัทปุ๋ย/โดรน/เครื่องจักร/แพลตฟอร์ม
3. **นำร่อง data space ระดับจังหวัด/สินค้า (2–4 ปี)** — เลือก 2–3 ห่วงโซ่ (ข้าวทุ่งกุลา/ทุเรียน/อ้อย) ผูกข้อมูลแปลง-คุณภาพ-ราคา-คาร์บอน พิสูจน์ว่าการแชร์ข้อมูลเพิ่มรายได้เกษตรกร (ต่อยอด AgriNEXT [7])
4. **กฎหมาย/นโยบายสิทธิ์ข้อมูลเกษตร (2–4 ปี)** — ศึกษาแบบ EU Data Act [3]: สิทธิ์เกษตรกรเข้าถึงข้อมูลเครื่องจักร/แพลตฟอร์มที่เก็บข้อมูลแปลงของตน + ข้อห้ามเงื่อนไขผูกขาด (lock-in) — ปรับใช้กับบริบทไทย
5. **ตลาดกลางข้อมูล + สหกรณ์ข้อมูล (4+ ปี)** — ตั้งกลไกให้เกษตรกร/สหกรณ์รวมข้อมูลขายหรือแลกบริการ (ต้นแบบ NASDA UK 95% [26], AgriAICoop [28]) — ผูกกับบริการ AI/ตรวจสอบย้อนกลับ/ประกันภัย
6. **เชื่อมโยงระหว่างประเทศ (4+ ปี)** — มาตรฐานข้อมูลไทยต้องสอดรับ CEADS/AgIN/ISOXML [15][19][37] เพื่อรองรับ EUDR/คาร์บอน/การส่งออก และป้องกันการถูก "เก็บข้อมูล" โดยไม่ได้รับส่วนแบ่ง [6]

### ตาราง Blueprint (ตามแม่แบบ)

| ขั้น       | ระดับฟาร์ม/ธุรกิจไทย                                                                                                             | ระดับนโยบาย                                                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 (1–2 ปี) | เกษตรกรแปลงใหญ่/สหกรณ์นำร่องใช้รหัสแปลงเดียว + บันทึกต้นทุน-ผลผลิตดิจิทัล ได้บริการ AI/คำแนะนำตอบแทน (รูปแบบยินยอมภาษาไทย)       | ประกาศ "มาตรฐานข้อมูลแปลงไทย" (สศก.+สพร.+เนคเทค [25][35][7]); เปิด API ชุดข้อมูลรัฐชุดแรก; คู่มือยินยอม PDPA-เกษตร [34]                                             |
| 2 (2–4 ปี) | data space นำร่อง 2–3 สินค้า (ข้อมูลแปลง-คุณภาพ-ราคา-คาร์บอน) — เกษตรกรได้ premium จากข้อมูลตรวจสอบย้อนกลับ (EUDR) [30]          | ร่างกฎหมายสิทธิ์ข้อมูลเกษตร (แบบ Data Act [3]); สนับสนุนสหกรณ์ข้อมูลผ่าน ธ.ก.ส./วิสาหกิจชุมชน; ต่อยอด AgriDataProv [32]                                             |
| 3 (4+ ปี)  | ตลาดกลางข้อมูลไทยเปิด (เกษตรกร/สหกรณ์ขายข้อมูลแบบ NASDA UK [26]); บริการ AI เกษตรไทยผูกข้อมูลของตัวเอง — ลดพึ่งแพลตฟอร์มต่างชาติ | นโยบาย "ข้อมูลเกษตรเป็นสาธารณูปโภค"; มาตรฐานไทยสอดรับ CEADS/AgIN [15][19]; กติกากำกับแพลตฟอร์มข้ามชาติเก็บข้อมูลแปลงไทย (เก็บไว้ในประเทศ/แบ่งปันผลประโยชน์) [6][27] |

## 9. ความท้าทายและข้อจำกัด

| ความท้าทาย                                    | รายละเอียด                                                                                                | โอกาสแก้                                                                              |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| ความไม่ไว้วางใจของเกษตรกร                     | ออสเตรเลีย 75% ไม่รู้ T&C, >ครึ่งไม่ไว้ใจ [5]; เคนยา กลัวภาษี/แอบแชร์ [6]                                 | ยินยอมแบบเข้าใจง่าย + สิทธิ์ถอนได้ + การแบ่งผลประโยชน์ชัด (ต้นแบบ NASDA UK [26])      |
| กฎหมายยังไม่ตอบ "ใครเป็นเจ้าของ"              | ข้อมูลแยกเป็น personal (PDPA/GDPR) กับ non-personal (ผลผลิต/เครื่องจักร) — ผสมกันแล้วระบุตัวได้ [6][27]   | ใช้กรอบ "data originator + data sovereignty" (EU [10][3]) แทนการไล่ "ความเป็นเจ้าของ" |
| Lock-in/ผูกขาดแพลตฟอร์มใหญ่                   | ข้อมูลติดระบบเดียว (FieldView/Ops Center) — เกษตรกรย้ายระบบไม่ได้ [27]                                    | Data portability + API เปิด (OADA [38], AgIN [35]); Data Act มาตรา switching [3]      |
| ข้อมูล derived/ผลลัพธ์ AI ไม่ตกเป็นของเกษตรกร | Data Act ครอบคลุม raw data แต่ Recital 15 ยกเว้นข้อมูลที่อนุมาน/ประมวลผลแล้ว (คำแนะนำปุ๋ย/ผลลัพธ์ AI) [8] | ทำสัญญาแบ่งผลประโยชน์ให้ชัด (ไม่รอพึ่งกฎหมาย) [8][27]                                 |
| ขาดมาตรฐาน/ราคาอ้างอิง                        | ตลาดข้อมูลยังไม่มีราคากลาง การตั้งราคาไม่มีหลักเกณฑ์ [2][27]                                              | งานวิจัย pricing + ตัวกลาง (data intermediary) ตาม Data Governance Act [3][27]        |
| ไทย: ข้อมูลแยกส่วน + ไม่มีแนวปฏิบัติ          | ข้อมูลหน่วยงานคนละระบบ/ไม่เปิด API ร่วม [25][33]                                                          | บัญชีข้อมูลกลาง CKAN [25] + ธรรมาภิบาลข้อมูลภาครัฐ สพร. [35] + data space นำร่อง      |
| SME/รายย่อยตกหล่น                             | Data Act ยกเว้น SME ผู้ผลิตเครื่อง → ช่องว่างในห่วงโซ่ [8]; เกษตรกรรายย่อยขาดอำนาจต่อรอง [6]              | ตัวแบบสหกรณ์/กลุ่ม (cooperative onboarding — AgriTrust [30])                          |

## 10. สมมติฐานที่ต้องตรวจสอบ (สำหรับ AI รอบหน้า)

- [ ] **"แพลตฟอร์ม AgIN ของ สวทช."** — การค้นพบจริง: ชื่อที่ใช้คือ "AgriNEXT" (เนคเทค-สวทช., ยัง R&D) และ "AgIN" ที่พบจริงคือของ AEF (ยุโรป) — ตรวจว่ามีแพลตฟอร์มชื่อ AgIN ของไทยแยกต่างหากหรือไม่ (สืบค้นเว็บ nstda.or.th/nectec.or.th เพิ่ม)
- [ ] **EU Code of Conduct ฉบับปรับปรุง** — เอกสารที่ยืนยันชัดคือฉบับ 2018; มีรายงานว่าอยู่ระหว่าง/มีฉบับปรับปรุง 2023–2024 — ตรวจวันที่/เนื้อหาฉบับล่าสุดจากเว็บ European Commission
- [ ] **ตัวเลข "ยอดซื้อขายข้อมูล" จริงของตลาดกลางข้อมูล** (Agrimetrics/JoinData/NASDA UK) — ยังไม่พบรายงานเปิดเผย; ตรวจ annual report/ข่าว 2026
- [ ] **ผลบังคับใช้จริงของ Data Act ต่อเครื่องจักรเกษตร** (เช่น John Deere/CNH เปิด API ให้เกษตรกร EU ฟรีจริงหรือไม่, ราคาหรือเงื่อนไขแอบแฝง) — ตรวจข่าว 2026–2027
- [ ] **สถานะ AgriSpace (มก.) และ GISTDA ในฐานะผู้ให้ข้อมูลแปลง/ดาวเทียม** — ตัวเลขสถานะ/ผู้ใช้งานปัจจุบันยังไม่ยืนยัน; ตรวจเว็บ KU และเว็บ GISTDA
- [ ] **การใช้ข้อมูลฟาร์มฝึกโมเดล AI ของบริษัทใหญ่** (John Deere See & Spray/Climate) — มีเพียงหลักการเปิดเผย (ADT 2024 [4]) ยังไม่มีตัวเลขเปิดของขนาดชุดข้อมูล/ค่าตอบแทน — ตรวจข่าว/คดีความสหรัฐฯ

## 11. อภิธานศัพท์

| คำศัพท์                       | ความหมาย                                                                                     |
| ----------------------------- | -------------------------------------------------------------------------------------------- |
| Data governance               | ธรรมาภิบาลข้อมูล — กติกาใครเป็นเจ้าของ/ใช้ได้/แบ่งผลประโยชน์อย่างไร                          |
| Data marketplace              | ตลาดกลางซื้อ-ขาย/อนุญาตใช้ข้อมูล (เช่น Agrimetrics, JoinData)                                |
| Data space                    | เครือข่ายแลกเปลี่ยนข้อมูลแบบกระจายศูนย์ภายใต้กฎร่วม (CEADS, AgIN, GAIA-X)                    |
| Data originator               | ผู้สร้างข้อมูล (EU Code 2018) — เกษตรกรเป็น originator ของข้อมูลการผลิต [10]                 |
| Data trust / data cooperative | องค์กรที่ถือ/จัดการข้อมูลแทนสมาชิก โดยสมาชิกควบคุม (NASDA UK, AgriAICoop)                    |
| Data Act (EU)                 | กฎหมาย EU 2023/2854 — สิทธิ์เข้าถึงข้อมูลเครื่องจักรของผู้ใช้; มีผล 2025-09-12 [3]           |
| Data Governance Act (EU)      | กฎหมาย EU 2022 — ตัวกลางข้อมูล/การแชร์แบบสมัครใจ; มีผล 2023-09 [3]                           |
| CEADS                         | Common European Agricultural Data Space — data space การเกษตรยุโรป (2025–2028) [15]          |
| AgIN                          | Agricultural Interoperability Network (AEF) — dataspace เชื่อม cloud ผู้ผลิตเครื่องจักร [35] |
| PDPA                          | พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (ไทย, มีผลเต็ม 2565) [34]                     |
| Interoperability              | ความเชื่อมต่อได้ระหว่างระบบด้วยมาตรฐาน/API ร่วม                                              |
| Data portability              | สิทธิ์ดึงข้อมูลของตัวเองย้ายไประบบอื่น (กัน lock-in)                                         |
| Consent                       | การยินยอมให้เก็บ/ใช้ข้อมูล (ต้องแจ้งวัตถุประสงค์และถอนได้)                                   |
| EUDR                          | EU Deforestation Regulation — ข้อมูลพิสูจน์แหล่งผลิตปลอดการตัดไม้ทำลายป่า [30]               |
| FRAND                         | Fair, Reasonable, Non-Discriminatory — เงื่อนไขแชร์ข้อมูลที่เป็นธรรม (Data Act Ch.III) [3]   |
| ISOXML/ISOBUS                 | มาตรฐานข้อมูลเครื่องจักรเกษตร (ISO 11783) [19][36]                                           |
| FAIR principles               | หลักการข้อมูลเปิด: Findable, Accessible, Interoperable, Reusable (เคนยารับไปใช้ [17])        |
