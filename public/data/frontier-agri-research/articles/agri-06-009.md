## 1. บทสรุปผู้บริหาร

- **ใจความ**: Multimodal AI = โมเดลเดียวที่ "เห็น+อ่าน+ฟัง+อ่านเซนเซอร์" พร้อมกัน (ภาพถ่ายใบ/แปลง + ข้อความถาม/คำอธิบาย + ตัวเลขเซนเซอร์ 05-007/05-008 + ราคา 06-004) — ตอบคำถามเกษตรกรแบบ "เห็นภาพแล้ววิเคราะห์ประกอบ" (ถ่ายใบข้าว → AI บอกโรค + เหตุผล + แนะนำ + คำนวณต้นทุน) — ก้าวข้ามข้อจำกัดของ AI แบบแยกส่วน (วินิจฉัยอย่างเดียว/แนะนำอย่างเดียว) [1][2][3]
- **ขั้นพัฒนา**: ⚗️ งานวิจัย/ช่วงเปลี่ยนสู่ผลิตภัณฑ์ (โมเดล multimodal เปิด (GPT-4V-class/LLaVA) ใช้ได้แล้ว — งานประยุกต์เกษตรเริ่ม 2024–2026; ผลิตภัณฑ์เชิงพาณิชย์ยังน้อย) [1][2]
- **ตัวเลขสำคัญที่สุด**: โมเดล multimodal (ภาพ+ข้อความ) วินิจฉัยโรคจากภาพ+บริบท (ถามประกอบ) แม่นยำ ~70–90% (งานประเมิน — เทียบแพทย์/ผู้เชี่ยวชาญพืช; ยังต่ำกว่าโมเดลภาพเฉพาะทางแต่ "ยืดหยุ่นกว่า"); การเพิ่มข้อมูลเซนเซอร์/อากาศประกอบช่วยความแม่นยำ/ความมั่นใจ (งาน ~+5–15%) [1][2][3]
- **นัยต่อไทย**: นี่คือทิศทางของ "ผู้ช่วยเกษตรกรรุ่นใหม่" (06-002 ยกระดับเป็น multimodal — ถ่ายภาพถาม+ผูกข้อมูลแปลง) — ไทยมีข้อมูล/งานภาพและภาษาไทยแยกส่วน แต่ยังขาด "โมเดลรวม" (ร่วมมือมหาวิทยาลัย/โมเดลเปิด) [4][5][6]
- **สถานะโดยรวม**: ⚗️ งานวิจัย/ช่วงประยุกต์

## 2. หลักการและขอบเขต

- **หลักการ**: โมเดล multimodal รับ "หลาย modality" พร้อมกันผ่าน encoder ร่วม (ภาพ: vision encoder; ข้อความ: language model; ตัวเลข: time series/sensor encoder) → "cross-modal reasoning" (เชื่อมโยงข้ามชนิด: เห็นภาพ+อ่านข้อความ+เห็นเซนเซอร์ → สรุป/แนะนำ) [1][2]
- **ประเภทโมเดล**: (1) ภาพ+ภาษา (VLM — GPT-4V/LLaVA/Qwen-VL-class) (2) ภาพ+ภาษา+ตัวเลข (งานวิจัยเริ่ม — เกษตร) (3) ภาษา+เซนเซอร์ (งาน IoT+LLM) (4) เต็มรูปแบบ (ทุก modality — เป้าหมาย)
- **การใช้งาน**: (1) วินิจฉัย "ถาม-ตอบด้วยภาพ" (ถ่าย+ถาม: "ใบแบบนี้เป็นอะไร" → วิเคราะห์+อธิบาย) (2) ผู้ช่วยแปลง (ภาพ+เซนเซอร์+อากาศ: "ควรฉีดยาหรือรอ") (3) รายงานอัตโนมัติ (ภาพ+ข้อมูล → สรุปผลเป็นภาษา) (4) การค้นคว้า (เอกสาร+ภาพ — ต่อยอด 06-002)
- **ข้อดี**: ใช้งานเป็นธรรมชาติ (ถาม/ถ่ายเหมือนถามคน), รวมข้อมูลหลายแหล่ง (แม่นยำ/ครบถ้วนขึ้น), อธิบายได้ (เหตุผล — 06-005)
- **ข้อจำกัด**: ต้องฝึก/ปรับแต่งข้อมูลไทย (ภาพ+ภาษาไทย), ต้นทุนประมวลผลสูง (ภาพ+ภาษา), ภาพหลอนยังมี (06-002), การประเมินในงานจริงยังน้อย
- **ขอบเขตที่ครอบคลุม**: เทคโนโลยี/สถานะ, การใช้งาน, ไทย, แนวทางใช้
- **นอกขอบเขต**: โมเดลภาพเฉพาะทาง (05-002/05-006), LLM ภาษา (06-002), foundation models (06-003)

## 3. สถานะงานวิจัย

| ช่วงเวลา  | ความก้าวหน้า                                                                                                                      | แหล่ง     |
| --------- | --------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 2022–2023 | VLM เปิด (LLaVA/OpenFlamingo — ภาพ+ภาษา); งาน multimodal เกษตรแรก (วินิจฉัยด้วยภาพ+ข้อความ)                                       | [1]       |
| 2024      | GPT-4V-class (ถาม-ตอบภาพ) ใช้ได้; งานประเมินวินิจฉัยพืช/โรคด้วย VLM (เทียบผู้เชี่ยวชาญ); งานเริ่มรวมเซนเซอร์+ภาษา                 | [1][2]    |
| 2025      | โมเดล multimodal เปิดหลายตัว (Qwen-VL/InternVL-class); งาน agricultural multimodal LLM (ปรับแต่งเฉพาะ); งานภาษาไทยเริ่ม (ภาพ+ไทย) | [2][3][4] |
| 2026–     | แนวโน้ม: "ผู้ช่วยเกษตร multimodal" เชิงพาณิชย์ (ถ่าย-ถาม-แนะนำ-ผูกข้อมูล), โมเดลเฉพาะภูมิภาค (อาเซียน/ไทย), มาตรฐานการประเมิน     | [3]       |

- **เส้นแบ่ง**: เทคโนโลยี "เปิด/เร็วมาก" — ช่องว่าง: (1) ข้อมูลฝึกไทย (ภาพ+ภาษาไทย+บริบท) (2) การประเมินในงานจริง (แปลง/เกษตรกร) (3) ต้นทุน (4) การผูกข้อมูลแปลง/เซนเซอร์ (06-006/05-007) — ผลิตภัณฑ์ยังน้อย

## 4. ผลลัพธ์เชิงประจักษ์ (ตัวเลข)

| ตัวชี้วัด                               | ผลลัพธ์                                        | เงื่อนไข      | แหล่ง  |
| --------------------------------------- | ---------------------------------------------- | ------------- | ------ |
| วินิจฉัยโรค (VLM — ภาพ+ข้อความ)         | ~70–90% (งานประเมิน)                           | ชุดทดสอบเฉพาะ | [1][2] |
| เทียบโมเดลภาพเฉพาะทาง                   | VLM ต่ำกว่าเล็กน้อย (เฉพาะงาน) แต่ยืดหยุ่นกว่า | งาน           | [2]    |
| การเพิ่มเซนเซอร์/อากาศประกอบ            | +5–15% (ความแม่นยำ/ความมั่นใจ — งาน)           | งานเริ่ม      | [3]    |
| ต้นทุนประมวลผล (ภาพ+ภาษา)               | สูงกว่าโมเดลภาพหลายเท่า (ช่วง)                 | เอกสาร        | [2]    |
| งาน multimodal ภาษาไทย (เริ่ม)          | มีงาน/ต้นแบบ (ภาพ+ไทย — มหาวิทยาลัย)           | งาน/TCI       | [4][5] |
| ผลิตภัณฑ์เชิงพาณิชย์ (multimodal เกษตร) | ยังน้อย (ช่วงเปิดตัว)                          | ตลาด          | [3]    |

- **กฎ**: multimodal "ดีกว่าการแยกส่วน" เมื่อผู้ใช้ถามแบบคน/มีบริบทหลากหลาย (ถ่าย+ถาม+ข้อมูลแปลง) — แต่ "งานเดียวซ้ำๆ" (วินิจฉัยภาพอย่างเดียว) โมเดลเฉพาะทางยังแม่นกว่า; ต้องเลือกใช้ตามงาน
- **เงื่อนไขสำคัญ**: (1) ข้อมูลฝึกไทย (ภาพ+ภาษา+บริบท) (2) ต้นทุนประมวลผล (ภาพ+ภาษา — ต้องบริหาร) (3) การผูกข้อมูลแปลง/เซนเซอร์ (06-006/05-007) (4) การควบคุมภาพหลอน (06-002/06-005) (5) การประเมินกับผู้ใช้จริง

## 5. ตลาดและการลงทุน

- **ขนาดตลาด**: multimodal AI ในเกษตร — ยังไม่มีตลาดแยก (เป็นฟีเจอร์ของผู้ช่วย/แอป); ตลาดผู้ช่วย AI เกษตร (06-002) ~1–4 พันล้านดอลลาร์ (2025 — analyst estimate ยังไม่ยืนยัน) [3]
- **ผู้เล่นหลัก**: โมเดลเปิด (GPT-4V-class/LLaVA/Qwen-VL/InternVL — ใช้/ปรับแต่งได้), ผู้ช่วยเกษตร (เริ่มเพิ่ม "ถ่ายภาพถาม" — 06-002 ผู้เล่น), งานวิจัย (มหาวิทยาลัยทั่วโลก/ไทย — มก./มจธ./จุฬา), ผู้ให้บริการโมเดล (OpenAI/Google/Meta/Qwen — ปล่อยโมเดล) [1][2][3][4]
- **การลงทุน**: ใช้โมเดลเปิด + ปรับแต่งข้อมูลไทย (หลักแสน–ล้านบาท/โปรเจกต์); การประมวลผลภาพ+ภาษามีค่าใช้จ่ายต่อคำขอ (หลักสตางค์–บาท); ไทย: เริ่มจาก "งานวิจัย+ต้นแบบ" (มหาวิทยาลัย) แล้วต่อยอดผลิตภัณฑ์ (ผู้ประกอบการ)
- **แนวโน้ม**: โมเดลเปิดถี่ขึ้น/ถูกลง, ผู้ช่วย "ถ่าย-ถาม-แนะนำ-ผูกข้อมูล" ครบวงจร, โมเดลเฉพาะอาเซียน/ไทย (ภาษา+ภาพ+เซนเซอร์), มาตรฐานการประเมิน
- **ความเสี่ยง**: ภาพหลอน/วินิจฉัยผิด (ความรับผิดชอบ — 06-010), ต้นทุนสูง, การตลาดเกินจริง (โชว์ได้ แต่แปลงจริงเพี้ยน), ข้อมูลไทยไม่พอ, การพึ่งโมเดลต่างชาติ

## 6. สถานการณ์ประเทศไทย

- **สถานะ**: งานภาพวินิจฉัยไทยมีอยู่แล้ว (05-002/05-009 — แยกส่วน); งานภาษาไทย/LLM เริ่ม (06-002 — Typhoon-class/OpenThaiGPT); งาน "รวมภาพ+ภาษาไทย" (multimodal) เริ่มมี (มก./มจธ./จุฬา — ต้นแบบวินิจฉัยข้าว/ทุเรียน); ผลิตภัณฑ์ multimodal เชิงพาณิชย์ยังไม่มี [4][5][6]
- **จุดแข็งไทย**: งานภาพและภาษาไทยแยกส่วนพร้อม (ต่อยอดรวมได้), โมเดลเปิดใช้ได้ฟรี, งานมหาวิทยาลัยหลายกลุ่ม, ข้อมูล/ภาพเกษตรไทยมีอยู่จริง (ต้องจัดระบบ)
- **จุดอ่อน**: ชุดข้อมูล "ภาพ+คำถามไทย+บริบทแปลง" ยังไม่มี (ต้องสร้าง), ทักษะ/งบ multimodal จำกัด, การประเมินกับผู้ใช้จริงยังไม่ทำ, ผลิตภัณฑ์/การตลาดยังไม่มี, การผูกเซนเซอร์/ข้อมูลแปลง (06-006) ยังไม่เชื่อม
- **โอกาส**: (1) "ชุดข้อมูล multimodal เกษตรไทย" (ภาพ+คำถาม+คำตอบ+บริบท — มหาวิทยาลัย+กรมวิชาการ) (2) ผู้ช่วย "ถ่าย-ถาม-แนะนำ" ภาษาไทย (ต่อยอด 06-002 — ต้นทุนต่ำด้วยโมเดลเปิด) (3) การผูกข้อมูลแปลง/เซนเซอร์ (06-006/05-007) (4) การร่วมมือกับผู้ให้บริการโมเดล (ภาษาไทย)
- **หน่วยงาน**: มหาวิทยาลัย (มก./มจธ./จุฬา/มข.), กรมวิชาการ/ส่งเสริม (ข้อมูล/ผู้เชี่ยวชาญ), สตาร์ทอัพ AgTech, ETDA/NIA

- **Q2**: การประเมินผู้ช่วย multimodal ไทยกับเกษตรกรจริง (แม่นยำ/การยอมรับ/การใช้ — ต่อยอด 14-003) — ยังไม่มี
- **Q3**: โมเดล multimodal ภาษาไทย (ปรับแต่ง VLM — Typhoon-class) สำหรับเกษตร — ยังไม่มีเปิด
- **Q4**: การผูกเซนเซอร์/อากาศ/ราคา (05-007/05-008/06-004) เข้าโมเดล (เหตุผลข้าม modality) — ยังเป็นงานวิจัย
- **Q5**: การควบคุมภาพหลอนในการวินิจฉัย (ความเสี่ยง — ต่อยอด 06-005/06-010) — ยังไม่มีมาตรฐาน
- **Q6**: ต้นทุน/การออกแบบบริการ (โมเดล+API — ความคุ้มสำหรับบริการไทย) — ยังไม่มี

| ---------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 1 (1–2 ปี) | งาน "ผู้ช่วยถ่าย-ถาม-แนะนำ" ต้นแบบภาษาไทย (ข้าว/ทุเรียน — มก./มจธ.+โมเดลเปิด — ต่อยอด 06-002); สร้างชุดข้อมูล multimodal ไทย (ชุดแรก) | ทุน "multimodal AI เกษตรไทย" (สวทช./NIA); แนวทางการเก็บข้อมูล/ความยินยอม (06-006/06-010)      |
| 2 (2–4 ปี) | ผลิตภัณฑ์ "ถ่าย-ถาม-แนะนำ-ผูกแปลง" (เซนเซอร์/ราคา — 06-006/05-007/06-004) — ผู้ประกอบการ; ทดสอบกับเกษตรกร 1 หมื่นคน (ประเมินผล)       | มาตรฐานการประเมินผู้ช่วย AI (ร่วม 06-005/06-010); การเปิดข้อมูลภาพ/ความเชี่ยวชาญ (กรมวิชาการ) |
| 3 (4+ ปี)  | "ผู้ช่วยเกษตรไทย multimodal" ระดับชาติ (ทุกพืช/ทุก modality — ภาษา/ภาพ/เซนเซอร์/ราคา) — ใช้จริงกว้าง (ผูก 06-002/06-008)              | นโยบาย "AI เกษตรไทยเป็นบริการสาธารณะ"; การรับรองความปลอดภัย/ความรับผิดชอบ (06-010)            |

## 9. ความท้าทายและข้อจำกัด

| ความท้าทาย          | รายละเอียด                             | โอกาสแก้                                               |
| ------------------- | -------------------------------------- | ------------------------------------------------------ |
| ข้อมูลฝึกไทยไม่ครบ  | ภาพ+คำถามไทย+บริบท ยังไม่มีชุดเปิด     | สร้างชุดข้อมูล (มหาวิทยาลัย+หน่วยงาน), การใช้โมเดลเปิด |
| ภาพหลอน/วินิจฉัยผิด | ความเสี่ยงสูง (คำแนะนำผิด)             | การควบคุม (06-005/06-010), การส่งต่อผู้เชี่ยวชาญ       |
| ต้นทุนประมวลผล      | ภาพ+ภาษา แพง/ช้า                       | โมเดลเล็ก/เฉพาะงาน, การแคช, การเลือกใช้                |
| การประเมินจริง      | ยังไม่ทดสอบแปลงจริง                    | งานภาคสนาม (Q2), มาตรฐาน                               |
| ทักษะ/งบ            | multimodal ต้องคน/เครื่องมือเฉพาะ      | ใช้โมเดลเปิด/cloud, ร่วมมือมหาวิทยาลัย                 |
| การพึ่งต่างชาติ     | โมเดล/API ต่างชาติ (นโยบาย/ค่าใช้จ่าย) | โมเดลเปิด/งานไทย, อธิปไตยข้อมูล (06-006)               |

## 10. สมมติฐานที่ต้องตรวจสอบ (สำหรับ AI รอบหน้า)

- [ ] **VLM วินิจฉัย 70–90%** — ตรวจงานประเมิน (ระบุโมเดล/ชุดทดสอบ/ภาษา)
- [ ] **VLM ต่ำกว่าโมเดลเฉพาะทาง (เฉพาะงาน)** — ตรวจงาน
- [ ] **เซนเซอร์/อากาศประกอบ +5–15%** — ตรวจงานเริ่ม (เป็นช่วง)
- [ ] **ต้นทุนภาพ+ภาษาสูงกว่าโมเดลภาพหลายเท่า** — ตรวจราคา/เอกสาร
- [ ] **โมเดลเปิด (GPT-4V/LLaVA/Qwen-VL-class)** — ตรวจเว็บ/ข่าวล่าสุด
- [ ] **งาน multimodal ไทย (มก./มจธ./จุฬา)** — ตรวจ TCI/ข่าวอัปเดต
- [ ] **ตลาดผู้ช่วย AI เกษตร 1–4 พันล้านดอลลาร์** — ตรวจ analyst report ระบุปี (ต่อยอด 06-002)
- [ ] **สถานะโมเดลภาษาไทย (Typhoon-class — multimodal)** — ตรวจข่าวล่าสุด

## 11. อภิธานศัพท์

| คำศัพท์                     | ความหมาย                                   |
| --------------------------- | ------------------------------------------ |
| Multimodal AI               | AI รับหลายชนิดข้อมูล (ภาพ/ภาษา/ตัวเลข)     |
| VLM (Vision-Language Model) | โมเดลภาพ+ภาษา (GPT-4V/LLaVA-class)         |
| Encoder                     | ชั้นแปลงข้อมูลแต่ละชนิดเป็นเวกเตอร์ร่วม    |
| Cross-modal reasoning       | การเชื่อมโยงเหตุผลข้ามชนิดข้อมูล           |
| Prompt                      | คำสั่ง/คำถามที่ป้อนโมเดล (ภาษาไทย)         |
| Grounding                   | การผูกคำตอบกับข้อมูลจริง (แปลง/เซนเซอร์)   |
| Hallucination               | ภาพหลอน (ตอบผิดแต่มั่นใจ — ต้องควบคุม)     |
| Fine-tuning                 | การปรับแต่งโมเดลด้วยข้อมูลไทย/เกษตร        |
| Multimodal benchmark        | ชุดทดสอบประเมิน (หลายชนิดข้อมูล)           |
| RAG (06-002)                | การค้นข้อมูลประกอบคำตอบ (เสริม multimodal) |
